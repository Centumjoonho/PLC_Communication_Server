## 2. 최종 목표

- 기존 프로그램과 동일한 화면과 기능을 제공한다.
- WinForms MVP 구조를 유지한다.
- View는 화면 처리만 담당한다.
- Presenter는 View 이벤트와 Service 호출을 연결한다.
- Service는 UserControl, Form, DataGridView를 참조하지 않는다.
- DB, PLC, API 통신 코드는 각 전용 클래스에 둔다.
- 전역 상태와 불필요한 싱글턴 의존성을 줄인다.
- 반복 수집, DB 저장, API 서버를 안전하게 시작하고 종료한다.
- 기존 프로그램의 API 및 DB 계약을 유지한다.
- 각 단계를 독립적으로 빌드하고 검증할 수 있게 작성한다.

필요 이상으로 프로젝트를 여러 개로 나누지 않고 기존과 같은 단일 WinForms 프로젝트를 유지한다. 자동 테스트가 필요해지면 테스트 프로젝트만 별도로 추가한다.

### 4.2 의존 방향

```text
UserControl(View)
        ↓ 이벤트
Presenter
        ↓ 호출
Service
        ↓ 호출
Database / Plc / Api / Store
```

### 4.3 반드시 지킬 규칙

1. View는 Service를 직접 생성하지 않는다.
2. View는 DB 또는 PLC 클래스를 직접 호출하지 않는다.
3. Presenter는 SQL이나 PLC 프레임을 처리하지 않는다.
4. Service는 Form, UserControl, MessageBox를 참조하지 않는다.
5. Model은 화면이나 DB 처리 코드를 포함하지 않는다.
6. 의존 객체는 `Program.cs` 또는 `MainForm`에서 생성해 주입한다.
7. 시작과 중지 메서드는 중복 호출해도 안전해야 한다.
8. 장시간 작업은 UI 스레드를 막지 않는다.
9. 공유 데이터는 복사본 또는 동기화된 Store를 통해 전달한다.
10. 예외를 빈 `catch`로 숨기지 말고 로그 또는 정상적인 종료 사유로 처리한다.

## 5. 복제 원칙

이번 작업에서 말하는 복제는 모든 파일을 한꺼번에 복사하는 것이 아니다. 기존 기능을 작은 단위로 옮긴 뒤 매 단계 검증하는 방식이다.

### 5.1 그대로 복사해도 되는 항목

- 화면 배치가 동일해야 하는 `.Designer.cs`
- 화면 리소스 `.resx`
- 이미지와 아이콘 리소스
- DB SQL문과 컬럼 이름
- PLC 요청 프레임의 바이트 규격
- API 요청/응답 필드 이름
- 사용자에게 표시되는 업무 용어

복사한 뒤 namespace, 클래스명, 이벤트 연결, 프로젝트 포함 여부를 반드시 확인한다.

### 5.2 복사 후 정리할 항목

- 단순 데이터 Model
- View 인터페이스
- `App.config`의 런타임 설정
- PLC 및 API 상수
- DB 연결 설정

하드코딩 값과 사용하지 않는 `using`을 정리한 뒤 사용한다.

### 5.3 코드만 참고하고 다시 작성할 항목

- `Program.cs`의 객체 조립
- `MainForm.cs`의 화면 전환 및 종료 처리
- `Reference.cs`
- `RuntimeState.cs`
- `ServerMainService.cs`
- Presenter 내부의 비동기 이벤트 처리
- PLC 반복 수집 루프
- DB 저장 큐
- API 서버의 취소 및 클라이언트 관리
- 공유 데이터 Store

이 항목들은 기존 코드의 책임 집중과 전역 의존 문제를 그대로 가져오지 않기 위해 새 구조에 맞춰 다시 작성한다.

### 5.4 복제하면 안 되는 항목

- `bin`
- `obj`
- `.vs`
- 기존 프로젝트의 `.csproj.user`
- 빌드 캐시
- 원본 프로젝트의 Git 내부 파일
- 실제 운영 비밀번호나 비밀키가 포함된 설정
