## 1. 문서 목적

이 문서는 `RO_Server_Rebuild_2` 개발이 끝날 때까지 사용하는 기준 문서다.

- 현재까지 확정한 설계를 기록한다.
- 기존 프로젝트에서 유지할 기능과 개선할 구조를 구분한다.
- 여러 기능을 한 번에 추가하지 않고 단계별로 빌드하고 검증한다.
- 개발 중 설계가 변경되면 코드보다 이 문서의 결정 기록을 먼저 갱신한다.

---

## 2. 최종 목표

- 기존 프로그램과 동일한 주요 화면과 업무 기능을 제공한다.
- WinForms MVP 구조를 유지한다.
- View는 UI 표시, 입력값 읽기, 이벤트 발생만 담당한다.
- Presenter는 View 이벤트와 Service 호출을 연결한다.
- Service는 `Form`, `UserControl`, `DataGridView`, `MessageBox`를 참조하지 않는다.
- DB, PLC, API 통신은 전용 클래스에 둔다.
- API 서버, PLC 반복 수집, DB 저장 작업을 안전하게 시작하고 종료한다.
- 기존 DB 컬럼, PLC Frame, API JSON 필드 계약을 유지한다.
- 전역 상태와 불필요한 Singleton 의존성을 줄인다.
- 다른 개발자가 실행 흐름을 쉽게 찾을 수 있도록 객체 생성 위치를 `MainForm`에 모은다.

## 3. 선배 조언을 반영한 핵심 원칙

### 3.1 코드를 불필요하게 복잡하게 만들지 않는다

- 한 곳에서만 사용하는 짧은 정책을 무조건 별도 클래스로 만들지 않는다.
- 클래스 이름과 실제 책임이 일치하도록 한다.
- 한 줄로 읽히는 문장은 불필요하게 여러 줄로 나누지 않는다.
- 같은 값에 의미가 없다면 불필요한 지역 변수와 중간 메서드를 만들지 않는다.
- 단순한 CRUD는 기존 메서드 이름과 흐름을 최대한 유지한다.

### 3.2 깊은 참조를 만들지 않는다

금지 예시:

```csharp
Reference.Instance.MainForm.UC_ServerMain.SomeService.Start();
```

```csharp
serverMainService.CollectionService.DataStore.Items.Add(data);
```

허용 방향:

```text
View → Presenter → ServerMainService
                       ↓
             ApiServer / PlcCollectionService
                              ↓
             PlcDb / PlcReader / RunRateService / DbSaveService / PlcDataStore
```

각 클래스는 생성자로 전달받은 바로 아래 의존 객체만 호출한다. 다른 객체의 내부 필드나 하위 객체를 연속해서 찾아가지 않는다.

### 3.3 큰 수명주기만 분리한다

별도 클래스로 유지할 대상:

- `PlcCollectionService`: PLC 반복 수집 시작·반복·정지
- `DbSaveService`: DB 저장 큐와 Worker 시작·종료
- `RunRateService`: PLC 상태와 가동초 계산
- `ApiServer`: Listener와 Client 수명주기
- `ApiHandler`: API 요청 검증과 응답 생성

별도 클래스로 만들지 않을 대상:

- `PlcFailurePolicy`: 생성하지 않는다.
- PLC별 실패 횟수, 스킵 종료 시각, 복구 판단은 `PlcCollectionService` 내부 private 상태와 메서드로 둔다.

### 3.4 인터록은 객체 Lock보다 실행 상태와 UI 비활성화로 단순하게 유지한다

- PLC 통신 중에는 PLC 등록·수정·삭제를 할 수 없다.
- API 서버 실행 중이거나 PLC 통신 중에는 DB/API 설정을 변경할 수 없다.
- API 서버가 상위 기능이다.
- API 서버 정지 요청은 PLC 통신 정지를 먼저 요청한 후 API Listener를 정지한다.
- PLC 통신 시작은 API 서버가 실행 중일 때만 허용한다.
- 버튼 이벤트 중복 실행은 Presenter와 Service 수명주기 양쪽에서 방어한다.
